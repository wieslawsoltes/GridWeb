# Excel feature audit · 0.8.0

Audit date: 2026-09-20. Starting source: `7195869c5950af0deecbdad1560429e87d705c49` (the complete main source tree, including its existing gitlink). This is a source-level feature inventory and a focused behavioral audit, **not an assertion that every Excel feature or API member is implemented**.

The 0.6 audit corrected stale 0.1.0 inventories (190 names versus 330 then present). This audit starts with merged 0.7, 356 names and 1,194 Node tests. Version 0.8 expands existing name/binding APIs without adding function names. `npm run inventory` now derives the inventories from live exports, public prototype members and all `src/**/*.js` modules. Regression tests reject inventory drift. [Function names](functions.json) and [API/module inventory](api-inventory.json) describe availability; they are not behavioral-conformance percentages. The current engine exposes **356 names**, including special forms and legacy aliases.

## What 0.8 changes and recovery audit

The interrupted naming work was recovered from recorded source edits onto the exact 0.7 baseline and retested. The final recovered tree has additional fixes and fresh qualification; it is not represented as the exact pre-interruption tree. Independent workbook/local collections retain stable definition contexts, hidden/comment metadata and legacy upsert/iteration behavior. Parsed renames repair only the intended free name uses and reject lexical capture, table/built-in collisions and meaning-changing shadowing. Reference-valued LET/LAMBDA bindings preserve identity/dependencies and memoize reference probes; named cycles report CIRC.

Reusable Define name, Name Manager and Create from Selection dialogs expose these operations with guarded writes, confirmed deletion, search/scopes, navigation, keyboard/focus behavior and responsive layout. The sample uses ordinary source/summary worksheets. New Office named-item and native/worker commands, declarations and installed consumers use the same engine. OOXML preserves ordinary local scope and rejects unsupported relative/null/deleted-context names. Name Manager edit+rename repairs recursive self-use in the same transaction. Qualified names no longer masquerade as omitted LAMBDA parameters; additional R1C1-shaped identifiers reject creation.

Release packing now records tracked gitlinks in `SOURCE-GITLINKS.json` instead of reading a submodule directory as a file. It never sweeps private/untracked submodule files and rejects symlink paths or reserved-manifest collisions. This addresses the earlier post-merge publication failure without changing the pinned Blazor runtime. Local packing is not registry-publication verification.

The live function inventory remains **356**, not a parity score. All feature areas below/above remain bounded profiles. See [naming contracts](defined-names.md) and [fresh verification](verification-0.8.md). Native assertions increase from 22 to 28 per framework; schema validation includes a standard scoped-name fixture. Actual remote outcomes belong to the exact PR/merge checks, not local test predictions.

## Previous 0.7 increment

The reference increment implements 3-D sheet spans for a declared consumer set, comma unions, whitespace intersections, dynamic colon ranges, reference-form INDEX, adjacent table-column selectors and shared A1/R1C1 reference scanning. Sparse reads preserve dependency/visibility identity without worksheet-sized allocations. It adds AREAS, ISREF, SHEET, SHEETS and seven A-suffixed statistics, taking availability from 345 to 356 names.

Worksheet insertion/reordering, endpoint-crossing/deletion repair and metadata/name rewriting are atomic and undoable. A deleted ordinary reference remains REF even when a new worksheet reuses its old name. Single-sheet row/column insert/delete that would change a live multi-sheet 3-D span rejects before mutation: exact grouped structural transformation is still pending. Version 0.8 supplies the documented direct reference-binding/local-name profile; remaining special forms and external names are still work.

The shared control owns Move worksheet, with stale-workbook/order checks and apply-time read-only enforcement. Home/Formulas → Reference tools creates real source/summary worksheets; source editing, reorder and undo all use the shared engine. Office worksheet.position, worker/host commands, typed C# extension methods, package consumers and declarations expose the same operation. The browser suite checks native keyboard interaction, focus isolation, mobile dark layout and lifecycle cleanup.

Native smoke coverage adds reference/insertion/move checks. Avalonia now waits for AdapterCreated and checks completion against the trusted host URI; initialization is cancelled during disposal. The preceding 0.6 post-merge CI failed on an Avalonia navigation timeout despite successful compilation and PR qualification. This is a recorded baseline failure, not hidden by reducing native checks; the new native minimum increases to 22 assertions per framework. Local .NET compilation is unavailable, so exact new native qualification is deferred to this change's CI evidence.

See [reference contract](reference-semantics.md) and [local 0.7 qualification](verification-0.7.md). The full source/API availability inventory is regenerated and checked against the runtime. Code review and these tests are not an exhaustive member-by-member Excel differential audit.

## Previous 0.6 increment

The calculation increment adds 15 available names: AGGREGATE, MAKEARRAY, ISOMITTED and 12 database functions. It also improves already-present SUBTOTAL and LAMBDA helpers. It corrects recursive LAMBDA error propagation and rejects unsupported nested helper arrays rather than silently taking their first element. Database criteria have an explicit cross-product work budget.

The editing increment is reusable without the UI: immutable copy snapshots, nine paste modes, four arithmetic operations, transposition and blank skipping within the documented profile; anchored month/year and weekday series; sparse special-cell queries. It fixes copied formula errors, format replacement, validation-origin translation and transactional rollback. Unsupported combinations are rejected before commit rather than partially applied.

The control owns the dialogs, so they are also available to other applications and React refs. The sample only wires commands and executable fixtures. Home/Data/Formulas expose Paste special, Fill series, Go to special and Calculation tools. Formula lab gains five examples without changing the five-sheet default workbook. Generic host/worker clients can invoke the new allowlisted routes. Installed-package/type tests cover the exported surface.

See [editing contracts](editing.md), [calculation contracts](functions.md) and [qualification](verification-0.6.md).

## Next implementation groups

1. **Reference and calculation completeness:** grouped 3-D structural transforms, reference preservation through remaining special forms/helpers, exhaustive reference-consumer/error rules, iterative calculation, full Unicode/relative/external names, shared coercion/signature metadata and Excel-generated differential fixtures. Add GROUPBY/PIVOTBY after their grouping/reduction/error contracts are specified.
2. **Editing, layout and accessibility:** merged/spill-aware copy/move, correct cut-reference repair, discontiguous selection/operations, richer autofill patterns, full rich clipboard, format/rule catalogs, IME/RTL/screen-reader/device testing and optional GPU presentation without a second document model.
3. **Office document fidelity:** preserve unsupported OOXML parts/relationships, future-function/dynamic-array metadata, chart/drawing and pivot-cache extensions, then add independent open/save/reopen fixtures. Keep native qualification separate from self-round-trip tests.
4. **Data platform and automation:** pivot hierarchies/slicers/date grouping, connections and refresh, Power Query/M and DAX/model execution, solver/scenario/data-table engines, additional binary formats, macro/add-in hosting with explicit trust boundaries.
5. **Runtime and collaboration qualification:** root/native/React/Blazor package identity, broader platform input/print tests, large-workbook benchmarks, character-level collaboration, robust offline reconciliation, identity/compliance and clustered persistence.

These are remaining engineering projects, not disabled features disguised as finished implementations. Full Excel parity is still unfinished.
